# 1.4 Concurrency and scheduling

One Targets worker orchestrates Find -> Check -> Plan -> Engine -> Library. Three hosted
services total: **PipelineWorker** (target claims, scheduling, follow/rule/request upkeep,
speculative checks), **EngineMonitor** (one engine tick/snapshots/completion/stall signals),
**MaintenanceWorker** (metadata/Fribb/browse refresh, file scans/operations, expiry, push,
desktop periodic jobs). Each service has bounded work queues, not a new service per job.
Maintenance dispatches module calls, never implements provider/file/decision logic.
Only its single leased Library executor performs FileOperations; Observe/startup enqueue
or reconcile proposals through it. Targets persists each returned stage under CAS.
Use monotonic time for active windows/deadlines; UTC for durable dates.

Each source/host has one priority queue and one HTTP gate shared by mirrors/adapters:
**owner** and **background** lanes, FIFO within equal target order. Request approval is
owner lane for the immediate action; unattended retries/rules/follows are background.
Different configured sites have independent gates; a bitsearch cooldown never holds Nyaa.
Site queue wait+spacing+all pagination/detail/mirror I/O must fit **6 s from source-task
enqueue**. If it cannot start in budget return TimedOut/Busy partial diagnostics without
calling upstream; never hold the whole acquisition behind patient 20/30 s line waits.
Admission of the *overall* action can wait durably for bounded capacity; “6 s” is not a
promise for the whole Find+Check+alias+file operation pipeline.

One logical source call, no inline retry, no generic fallback on auth/rate-limit errors.
A capability-negotiated Torznab endpoint choice is allowed inside that same deadline.
Pagination/1337x detail fanout bounded by remaining deadline and pool cap 80/source
(ask at least 50 where supported); partial results stream immediately with completeness.
Malformed RSS is SourceFailure, not successful empty. XML DTD/resolver disabled;
TLS never bypassed. EZTV raw coordinates are not trusted: Parser/Plan independently
reject wrong seasons (OPS-652); malformed TorrentDownloads feed stays diagnosed (OPS-653).

429 or 503 **with Retry-After** sets per-site cooldown: honor delay/date (do not cap a
server-supplied larger delay). Missing/invalid header on 429 defaults 30 s; repeated such
429s exponential up to 300 s; successful requests reset strikes. HTTP 503 without
Retry-After and transport errors have no made-up cooldown; next scheduler sweep retries.
During cooldown skip immediately with due time, no waiting/retries. Settings tests may
explain cooldown but do not ignore it. Courtesy spacing is not an owner app-level quota.

## Bounded budgets, fairness and cancellation

Defaults (typed settings, benchmark-adjustable):

| Resource | Bound | Admission policy |
|---|---:|---|
| Active film/season pipeline scopes | 8 | at most 2 background; remaining owner reserve |
| Adapter calls | 24 globally | background <=8; per-host limits above still apply |
| Background searches | 2 scopes concurrently | concurrency only; NO per-minute owner/request budget |
| Swarm checks | 10 total | background <=2; priority queue and shared hash flights |
| Speculative target set | 2 targets x top 3 hashes per tick | skip live hashes/fresh verdicts; no overlapping tick |
| Pack mappings | at most 4 per scope | metadata already obtained in Check, no second probe engine |
| Metadata wait | max 3 top Unknown hashes per target, shared hash handles | outside payload cap, no payload; global 10 Check attachments/physical peer bounds still apply; 45 min lifetime |

No busy result becomes a user-facing immediate failure. Wake durable queue on capacity
release and setting change. Owner arriving prevents **new** background admission, not
destructive cancellation of downloads; already running source/probe tasks drain within
their short deadlines. With endless owner work background may wait; show honest next
try/capacity state, not falsely increment miss counters.

Search-flight identity: normalized query, work/scope (year/kind/season/numbering version),
source/category/selected source IDs, source and credential revisions, parser version,
English-vs-fallback phase. NO quality/size/audio/target policyRevision in HTTP flight keys.
Use **Lazy<Task> inserted
before task start** (OPS-654), not eager Task in GetOrAdd. Promoting a background flight
to owner priority does not duplicate HTTP. Individual waiter cancellation just detaches;
the shared flight owns its CTS and bounded deadline, cancels only when no subscribers
and no durable intent remains. Clear flight entry with identity guard on completion.

30-min SearchCache is per successful complete source answer; assemble shared pools by
normalizedQuery, newest unexpired matching revision, not guessed opaque cache keys.
A partial/error/timed-out/skipped source isn't written as a complete negative cache.
Fresh source answers can be reused while absent failed sources are retried next sweep.
Early-stopped pools are explicitly partial; never pretend every source returned.
Maximum in-memory completed pools 200, LRU; DB TTL cleanup by Maintenance.
Quality changes rerun each waiter's Plan with fresh own policy/ownership; they never split
or invalidate shared source HTTP flights. First waiter's quality/cancellation cannot win
another waiter's choice (B06). SearchRequest.Policy describes downstream Plan context,
not source-result identity. Query/scope changes alone select a different HTTP flight.

## One season pool, English first, early stop

For film: English title+catalog year, then guarded punctuation variants. For series:
one shared `English show SNN` plus broad `English show` pool; parse all episode forms.
Finished seasons pool packs+singles **immediately**, not after two misses or a flag.
Still-airing seasons do not automatically acquire a pack. Confirmed file mapping selects
only missing wanted episodes. For uncovered gaps use episode/absolute variants against
the same pool/cache, not a full fanout separately for every known episode.

Find does not decide viability. It streams candidates; Targets supplies Check+Plan
feedback through SearchFeedback. A Good/Weak verdict **and all gates passing** covers
an item. Stop outstanding source work once every requested missing item is so covered
(film = one). Do not stop a season when only one episode is found. Waiting for an already
in-flight check is bounded 20 s; it does not extend a source deadline.

Core English exhausts/has no usable coverage -> fallback English only for gaps.
No good/weak English candidate after core+fallback -> original/romaji then approved
synonyms for gaps, in metadata order, same two tiers. An Unknown candidate does not
block fallback names. Unknown-language is acceptable, clearly foreign refused.
If English label absent use provider display fallback, record that fact, don't invent
a translated name. Broad title matching still checks aliases/year/kind (Scorpion !=
Scorpion King). Failed metadata lookup is unknown, never a fallback guessed identity.

## Check and ranking

Check inside the one MonoTorrent client, unique hash flights. Top 3 structurally plausible
candidates per target, dedup across season targets; next tranche only if rejected/weak.
20 s **attachment+measurement total**, independent queue wait reported separately.
Require hash-bound file list for safety/pack mapping. Tracker scrape can prefilter
ordering, not eliminate on zero alone; scrape budget <=1.8 s both lanes, batches <=74,
cache <=5000 hashes, 3 answered trackers +250 ms grace.

| Evidence in a fresh completed probe | Band / policy |
|---|---|
| >=256 KiB delivered, >=64 KiB/s over >=4 s, >=1 byte-sending peer | Good; stop early once file list available |
| >0 delivered, insufficient Good threshold | Weak |
| reached connected peers throughout observation, no hash-valid bytes in full window | Dead for this measured window |
| no reached peers, transport/metadata uncertainty, expired/invalid cache | Unknown, not Dead |

These thresholds replace playback bitrate/headroom; tunable via Check settings in
engine section. Good/Weak/Dead cached 6 h; **wanted-target Unknown TTL 45 min** (speculative
Unknown default 6 h), named by Release; cancellation never
persists. Existing live transfer is sampled read-only and never removed, reprioritized
or written into reusable Verdict. Fresh unknown is skipped in speculative ticks.
Recent verdict listing corrects expiry to Unknown at read time and bulk-loads hashes.

Phase 3.5 implementation settings: engine `CheckWindowSeconds=20`, `GoodBytes=262144`,
`GoodBytesPerSecond=65536`; `TorrentFlow:Check` configures minimum Good observation
4 s, total slots 10, background slots 2, queue wait 60 s, verdict TTL 6 h,
wanted Unknown TTL 45 min and probe version 1. Queue expiry returns Unknown with
zero measurement, never Dead. Good/Weak/Dead version fingerprints bind the configured
window/thresholds and algorithm version; changing them invalidates classification
without expiring the Release file metadata. Unknown uses the algorithm version, and a
wanted caller bounds even a speculative Unknown by checkedAt + 45 min. Dead requires metadata and at least one connected peer
in every engine sample of the full observation, not merely a peak connected-peer count.
Less than 4 s of observation after attachment cannot establish Dead.
Attachment time consumes the measurement budget; capacity wait is separate.
Probe-only callers release all capabilities before returning. A pipeline that needs
immediate admission explicitly requests retention of the engine's <=30 s capability.
Check returns unsaved evidence; Targets' composition persists it atomically through
the Domain cache port (including immutable Release file metadata). No scrape-derived
zero is used to eliminate a candidate; probes run regardless of listed seed counts.

Probe ownership is a capability handle; if a live hash can't confidently be distinguished,
fail closed on attaching another probe (Unknown), never remove somebody else's manager.
No application Download row is created for a probe. A Download row of ANY intent (even
detached Queued/Paused/Stopped) bars AttachProbe; read live evidence or return Unknown.
Per-hash mutex serializes attach/release/admit/recover/file rebind. AdmitFromProbe consumes
ownership exactly once with drain+invalidation/recheck or safe manager transfer; a late
probe release can never remove the admitted manager. Metadata wait shares this contract.
Admission claims reserve the hash before Store commit; fresh checks hand back a <=30 s
capability, not a released manager. Claims expire in 90 s and failed commits release them.
Recover registers ALL persisted Download hashes before checks start, avoiding a paused
hash probe attachment even when no live manager exists.
Bounded selected pieces may use
engine-data probe files; they are not library payload/staging. **MonoTorrent 3.0.2 hazard:**
per-hash piece cache must be explicitly invalidated, pending disk writes drained, and
real admission hash-checked after probe detach. Phase 3 gate must prove no cross-hash/live
contamination on the actual package. If those guarantees cannot be obtained, reuse the
probe's manager by ownership-transfer+full recheck; do NOT launch a second client as a
silent workaround. Block Phase 3 pending engine/package fix if neither works.

### Unknown metadata acquisition without payload

After core/fallback/name tiers find no eligible Good/Weak, attach max 3 structurally
plausible top Unknown candidates per wanted target **metadata-only**, outside download cap.
Dedupe pack/hash across targets; scheduler fairly shares the global attachment budget,
not 3 separate managers for each pack episode. No selected payload bytes, reserved library
paths or payload slot; Engine may exchange torrent metadata only. Persist waiting
WaitingForSeeders with nextTry <=45 min; capabilities expire after 45 min and are released
on cancellation/ownership change/restart (reconstruct from intent, not Attempt).
Metadata arrival triggers T39 -> planning after hash-bound safety/file mapping, then normal
Targets admission. No peers stays Unknown and honestly waits, not permanent NoHealthyRelease.
Long metadata waiting is distinct from the 20 s health probe; no indefinite probe slot.

For torrentUri sources fetch the `.torrent` through the existing bounded Engine metadata
HTTP facility (20 MiB, source deadline/SSRF/hash checks) to obtain complete file lists
without peers. Check returns this hash-bound metadata; it does not prove live health.
Never blindly use torrent filenames as catalog identity or download before Plan gates.
When metadata exists, Unknown can be selected only after all Good/Weak/name alternatives
are exhausted, and displays Waiting for seeders until actual payload progress.

Plan ranking lexicographic: all hard gates first; Good > Weak > Unknown (Unknown only
if safe metadata exists and no eligible Good/Weak after all queries); Dead never.
Within same band connected byte-sending peers then measured delivery; then exact preferred
resolution, nearest higher; lower only if no explicit floor and policy allows it. An
explicit selected resolution is ALWAYS a floor; unknown/lower never qualifies.
Then encode/source preference, upload recency, conservative seeds, stable hash tiebreak.
Finished-season set cover uses the same order: healthy pack beats weak singles, select
only wanted missing files, tie by coverage/union-piece bytes; no separate pack picker.
Gate size per selected item/runtime, not whole pack; count boundary-piece union for disk.

Default size sanity (adjustable, reasons logged): reject <=0 known video bytes, obvious
CAM/TS and archives/programs; largest completed kept video >=1 MiB. Planning bitrate
minimums 0.1 Mbps SD/0.3 Mbps 720p/0.5 Mbps 1080p/1 Mbps 2160p, maximum 100 Mbps
per video when runtime known; absent runtime/size means unknown, not automatic rejection.
Owner maxBytes and quality floor are hard constraints. Validate against corpus/hard set
before implementation gate accepts these deliberately broad anti-fake defaults.

## Engine safety limits

Persist configured listen port (if 0 choose free once and save before bind); unavailable
port -> choose/save one fallback, log reason. One client uses DHT/PEx/local discovery/UPnP,
RC4/plain encryption; private torrents get no added public trackers. Tracker refresh 24 h.
Default 400 global peers, 120 per payload torrent, 40 half-open, probe limit 12 per hash,
probe global reserve <=120 (counts INSIDE 400); payload work gets priority.
32 MiB write cache, 40 open files; 20 MiB torrent metadata HTTP response and 32 MiB
webseed response buffers even when Range ignored. Metadata attachments consume Check
slots, not download cap. Targets alone decides payload cap/windows/Now, Engine receives
plain Run/Stop and enforces only physical bounds. Replacement shares the Current slot,
including pack swaps; its extra physical peers count toward global bounds. Download.intent
is Targets' same-commit admission cache, never Engine-owned state.
Detached paused/queued/completed rows retain no idle peer cache.
EngineMonitor ticks 5 s and emits exact selected-file snapshots, never writes Target.
Seeding stops for **all** completed downloads, including adoption; no import exception.

## Dynamic scheduler and release calendar

Sort eligible work each admission, not once at queue creation:
1. explicit Download now;
2. owner-assigned rank (ascending signed Int64);
3. fresh releases around metadata air/digital window;
4. approved requests;
5. followed back catalogue;
6. upgrades/watches/speculative checks.

Tie: rank, accepted click time, work ID, padded season/episode, target ID. Drag ranking
renumbers sparsely (1024 increments) transactionally; equal ranks deterministic.
Explicit owner ranking removes automatic Fresh promotion for that target. Pack gets
best target order; lowering cap demotes worst non-Now manager. Re-evaluate when dates,
rank, settings or ownership change. Download-now bypasses approval/cap/windows only.
Target stores nowAt, ownerRanked/rank and provenance, NOT TargetPriority. Compute priority
each sort from current open approved RequestItems, enabled Follow/Rule, expectedAt and
clock, Replacement intent/watch. Fresh window is expectedAt-2 h through expectedAt+48 h;
unknown expectedAt never promotes. Cancellation/disabled Follow/window aging changes order
without rewriting a derived class. TargetPriority is a transient enum, not a DB column.
RawIntent uses the same explicit owner inputs and accepted timestamp, no request promotion.
An ordinary owner click without Now/explicit rank uses FreshRelease if in its air window,
otherwise BackCatalogue (owner lane for the immediate search); it is not an implicit
OwnerRank or permanent Now. Origin remains provenance, not a stale priority class.
Pipeline leases renew every 20 s (90 s lifetime); renewal failure fences local results,
detaches only its shared-flight waiter and cleans private handles.

| Relative release window / condition | Retry default |
|---|---|
| Before confirmed release | nextTryAt=expectedAt+5 min, refresh metadata as due |
| 0..2 h after release | every 5 min |
| 2..12 h | every 15 min |
| 12..48 h | every 1 h |
| 2..7 days | every 6 h |
| Older backlog with substantive miss | every 24 h |
| Upgrade watch | every 24 h; notification only |
| Unknown dates | metadata refresh >=1 h, no fabricated aired status |
| Source cooldown | next feasible site due time, other sources continue now |
| No space/offline/window/cap | setting/root/slot wake; safety periodic recheck 5 min, window exact next opening |

Add deterministic ±10% jitter for background retry groups, never move before expectedAt.
No flat legacy 1/5/15/60/180/360 ladder. Store nextTryAt/reason so restart stays honest.
Honour weekly local-time windows (<=14), overnight and DST: invalid local times advance
to first valid instant, repeated time uses first next occurrence; ordered overlap policy
matches old DownloadWindows. Rates <=Int32.MaxValue. Now bypasses windows, not safety.

Calendar is a projection of the **same** Work release dates/Episode air times and Target
states over Follow, WatchItem and open Requests: expected/searching/found/downloading/
in library. Requesters see own request items only, read-only. Owner calendar follow/
unfollow/quality/grab-as-soon commands reuse intent APIs, not another scheduler.
Speculative checks at most every 30 min (startup 45 s), yield 1 min if owner busy,
disabled poll 5 min; scope Off/Watching/Monitored maps to WatchItem.status/Follow.enabled.
No full catalog sweep or playback dependency.
