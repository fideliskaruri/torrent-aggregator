# 1.5 Library placement, import and removal

Library owns all paths, names, filesystem validation, scans and deletion. Engine only
writes bytes to **the per-file absolute paths Library gives it**; Engine never generates
catalog folders, relocates or independently deletes payload. Placement happens when
hash-bound torrent file metadata arrives, **before payload**. One final folder, no
`.staging`, no cross-folder “promotion”.

## Exact compatibility with today's layout

Evidence: `server\TorrentFlow.Core\Contracts\Engine\WorkPlacement.cs:MediaFolders`,
`server\TorrentFlow.Engine\Settings\SmartSendTarget.cs:ForWork`,
`server\TorrentFlow.Engine\Layout\ContentLayoutPlanner.cs` and `ContentLayoutPolicy.cs`.
The baseline's 27 engine rows use `TV\<English show>\Season 01`; real video basenames
include `Rick.and.Morty.S01E04.1080p.HEVC.x265-MeGusta.mkv`, **not a new invented
`Show - S01E04 - Episode name` scheme**.

| Logical library kind | Default on a new root | Existing/migrated physical folder | Item folder | Video basename |
|---|---|---|---|---|
| Movies | Movies | category path rule, else Movies | `Safe English Title (Year)` | sanitized original torrent basename |
| TV | TV | category path rule, else TV | `Safe English Show\Season NN` | sanitized original episode basename |
| Anime | installation's existing name, normally **Anime Series** | **Anime Series** or actual existing configured Anime | pinned existing show folder, else `Safe English Show\Season NN` | original fansub basename, mapped by metadata |
| Anime Movies | Anime Movies | Anime Movies | `Safe English Title (Year)` | original anime-film basename |

**Resolved discrepancy:** plan names the logical library “Anime”, but current code
physically uses **“Anime Series”**, flat beside “Anime Movies”. Migration stores that
folder in StorageRoot.libraryFoldersJson and **does not rename existing roots or files**.
New roots default to the installation's existing kind folder names (Anime Series here);
only explicit owner configuration chooses Anime. Jellyfin's existing library paths and
items remain unchanged; adding a new root adds that root's matching kind folder to the
same Jellyfin library. Never nest Anime Movies inside Anime/Anime Series.

`Safe` matches MediaFolders.Name: replace `[<>:"/\|?*\x00-\x1f]` with spaces, collapse
whitespace, trim trailing dots/spaces, cap at 120 chars and trim. Add a Windows reserved
device-name guard (`CON`, `PRN`, `AUX`, `NUL`, `COM1..9`, `LPT1..9`, including extension):
prefix `_`. Empty becomes a stable short Work ID, not an arbitrary torrent title.
Film year appended exactly once when `(year)` already present; year is provider's valid
1870..2100, otherwise Parser release year for explicitly unresolved raw import only.
Series folder omits year exactly as today. Same-name series collision must be reviewed
or use an explicit disambiguated root/item folder override, never merge by name.
Season format `Season {number:00}` (minimum two digits, not truncate 100).
WorkFolder pins the **item folder and root** per work. Existing romaji/old-title folders
stay exactly as-is even after English display/search refresh; place later episodes beneath
that same pin. Migration records actual existing folders. Multiple conflicting folders
require reviewed selection, not auto-tidy. English names are only new-work defaults.
Only explicit owner MoveTitle/rename changes the pin with verified inventory operations.

Leaf layout ports ContentLayoutPolicy, not its unsafe same-sized overwrite exception:
- Torrent's outer container is redundant by construction; drop unless protected/structural.
- A deeper wrapper is dropped only when it repeats destination or matches all meaningful
  release tokens of a removed wrapper; single-child alone is insufficient (depth <=8).
- Preserve BDMV/VIDEO_TS/AUDIO_TS/CERTIFICATE/disc structure; protected disc releases
  remain subject to Plan safety/no-video rejection, not flattened blindly.
- Season/subtitle/extra structures preserve meaning; normalise provably named multi-season
  folders to Season NN only where destination does not already name a season.
- Flatten episode wrapper folders only when one unambiguous episode identity matches.
- Preserve video leaf filename, including resolution/group tags. Associated subtitles
  move beside video and use the video stem plus language/forced suffix and old extension.
- Extras collisions get a hash-specific namespace, **video collisions never overwrite**.
  Duplicates are surfaced to owner; use a hash suffix for a deliberately accepted new
  replacement, not auto-adopt another file because its size matches.

## Partial names and completion

For kept video/sidecar paths, reserve final physical key and write `<final>.partial`,
e.g. `...\Season 01\Rick.and.Morty.S01E04.1080p....mkv.partial`.
All partials are in the **same final directory**; Jellyfin must ignore the .partial
extension. Phase 5 gate actually scans Jellyfin mid-download to prove this, not assume it.
An upgrade's reserved final basename is `<stem> [<hash8>]<ext>` if original collides.
Old file is not renamed/deleted to make room.

Each skipped torrent file maps to
`<item-folder>\.unwanted\<full-hash>\<file-index>\<sanitized-relative-path>.partial`.
Create `.unwanted\.ignore`, set directory hidden on Windows, refuse reparse-point
ancestors. Skipped files get priority zero; unavoidable shared boundary pieces are sparse
fragments there. No video or orphan .nfo/sample fragment in Jellyfin's visible folders.
**Option (a), chosen:** per-file completion goes through Engine, never direct rename
while a manager still holds the partial path. Require ALL pieces touching video+selected
sidecars complete, including shared boundary pieces; a 100% file byte counter alone is
insufficient. Targets records the FileOperation+final binding intent/claims, then Engine
PrepareFiling drains writes, marks these files DoNotDownload and rebinds their path
(MonoTorrent MoveFileAsync/path-rebind facility, proven in Phase 3/5) before Library's
same-directory atomic rename without overwrite. Engine grants a file/path-scoped permit
that bars writes until CompleteFiling acknowledges publication or safe rollback.
No catalog naming logic or independent payload relocation is put in Engine.
Detach the pack manager ONLY when no selected file remains incomplete; E2-E10 continue
while E1 files safely. Retire E1's Current association, not the others. Seeding always stops
when the selected set completes; no origin exception.

Targets commits verified MediaFile+done+RequestItems together. DownloadFile reservation
paths become NULL, but `enginePath` is the rebound final path and `filed=true`, selected=false.
Recovery keeps filed bindings at final paths/DoNotDownload and hash-checks boundary pieces,
never recreates `.partial` or re-downloads filed episodes. Metadata and final bindings
outlive per-target Current links for a continuing pack.

**Option (b), mandatory fallback:** if Phase 3/5 engine proof cannot demonstrate safe
per-file path rebind+restart, wait until the **whole selected set** completes, detach/drain
once, then file all pack targets. Targets stay fetching/finalizing until this condition;
never ship unsafe per-file filing as a workaround. Document the proof result before choice.
Associated sidecars must finish before item done. Partial rename failure -> filing/waiting
FileBusy, never Ready. Remove skipped fragments and prune .unwanted/hash empty dirs.
`.ignore` remains as protection for future downloads.

Validation: head <=64 KiB + three 4 KiB zero checks; largest kept video >=1 MiB,
container signature accepts known media and refuses archive/program/zero-filled payload.
Unreadable is not invalid: retry 1 s then 2 s, otherwise FileBusy and queued operation.
In-process MKV/MP4 readers collect available codec/HDR/tracks/runtime; no ffmpeg/ffprobe
and **no unknown-language wait**. A clear foreign release is refused by Plan before
download. A signature-confirmed executable masquerading as .mkv becomes global Block.

## Multiple roots and capacity

1. Explicit owner-selected root/path must be validated and persists for the action;
   never accept requester savePath. Category paths become root library-folder mappings.
2. WorkFolder pins existing series videos **inside roots** to root+item folder. If several
   roots hold a series, choose the root of the selected season, then most episodes,
   then root priority/ID; owner can explicitly move the title. Do not split series
   automatically just because its pinned drive is full/offline.
3. New title with no existing item-folder pin: enabled online roots accepting
   logical kind, highest priority first (ascending number), fill until reserve reached,
   then next. Store path claims before start. Roots can have custom kind folders.
4. None fits -> wait “No drive has space”; pinned offline -> “Drive is offline”.
Track-in-place external work stores an external absolute item-folder pin; new episodes
wait for explicit owner enrollment/placement/move rather than silently making a second
series folder under a managed root. That pin never authorizes arbitrary external writes.

Sample physical free space at admission; reserve >=500 MiB default per root, preserve
owner maxStorageBytes if set. Selection reservation is the union of touched torrent
pieces including skipped boundaries, minus already allocated hash-valid pieces, plus
other committed outstanding reservations. Unknown size conservatively reserves 1 GiB
per item until metadata settles; a metadata-less magnet cannot start payload anyway.
Physical hard reserve cannot be bypassed by Download now; owner guardrail override may
change soft maxAllocatedBytes only. Use actual allocation, not bytes*progress.
Incomplete/unreadable subtree inventory reports incomplete and never implies 0 bytes
or deletes missing records (OPS-657). Re-check changed free space before admission.
Removing a root means disable it until its references are relocated/explicitly removed.

## Scan, track-in-place, move, copy, adopt

Scan is read-only proposal until owner confirmation. Parser receives filename **and**
parent folder as separate evidence; Metadata resolves work IDs and exact stable episode
mapping. Review classes Confident/NeedsPick/Unmatched; multi-episode ambiguity and
duplicates require choice. No unmatched media is arbitrarily assigned.
Only videos with signature validation can establish ownership (OPS-655). Subtitle/audio
sidecars follow selected video; nonmedia files left alone. Record scan coverage; reject
changing files and link-swapped paths (size/mtime before and after read plus physical key).

| Confirmed mode | Operation | Proof and deletion |
|---|---|---|
| Track in place | MediaFile root NULL if outside roots, absolute path | sniff/identity/mtime evidence; do not rename/delete source |
| Move | FileOperation, copy to destination partial if across volume; same-volume safe rename if safe | SHA-256 source/destination, size+stable mtime, signature; publish destination, then delete exact source |
| Copy | same verified destination publication | keep original; original not silently counted as second managed download |
| Adopt external torrent | read-only resume/.torrent mapping, present paths tracked in place | hash-check pieces; ambiguous layout rejected, missing-data transfer stays paused; no source client mutation |

Copy may optionally track the source too only when owner selected it; otherwise source
is outside managed inventory and never cleanup-owned. Duplicate candidates display all
locations/quality and ask which to keep; origin stays invisible.
External scanner preserves qBittorrent/Transmission/uTorrent/BitTorrent/Deluge support,
32 MiB input/10000 entries/20 s API bound; snapshot SQLite+WAL consistently before reading.
Never control external clients by default. Adoption's completion stops seeding too.

Root disconnected/unreadable means MediaFiles Offline, still Owned. Online requires the
root's `.torrentflow-root` content == StorageRoot.id AND matching volume serial/physicalKey;
readable empty mount points or reused letters with wrong/missing marker are Offline.
Enrollment writes marker only with explicit owner confirmation, never recreates it during
a scan. Per-root mass vanish **>10% OR >20 files in one scan** -> root/files Offline,
ask owner, suppress Missing/pruning/reacquisition. Count over prior inventory of that root,
not only a readable subtree. Owner resolves the guard after checking volume/paths.
Persist StorageRoot.reviewRequired; a later readable scan does not silently clear it.

Only complete identity-valid, non-guarded scans record Missing: first missingSince,
then a second complete scan **at least 6 h later** sets missingConfirmedAt. Until then
ownership exclusion protects the item against ANY acquisition (including manual season,
request/rule/follow and T29); report “Checking missing files”. Returning file clears both.
Offline/incomplete scans cannot count as either confirmation. Retain confirmed Missing
30 days from confirmation then prune; no auto-redownload/pruning for offline. Target/request
settlements remain historical. Return honest Files missing versus Drive offline.
Scan never follows junctions/symlinks and never claims paths in pending operations.

## Swap, delete and move correctness

FileOperation is the only durable queue for rename/copy/move/delete. Library returns
unsaved proposals; Targets commits stages/inventory jointly. Persist exact
expected identity, size, digest and bounded source/destination, verify before action;
on restart inspect both sides and advance idempotently, or stop with an owner reason.
No side JSON relocation/deletion journal.

One executor in MaintenanceWorker handles filing, delete, import, relocation and startup
recovery; EngineMonitor/PipelineWorker only enqueue or request its work. CAS leaseToken/
leaseUntil (60 s, renew 15 s) and FilePathClaim U(physicalKey) serialize BOTH source and
destination. Claims remain through retry/NeedsOwner; only Done/Superseded releases them.
Never hold a database transaction during filesystem work.

| From -> To | Durable proof / action |
|---|---|
| Pending -> Copied | Executor owns lease+both path claims; Engine permit or detach+drain proof; copy into destination partial or atomic same-directory rename; Delete/no-copy uses explicit no-op stage |
| Copied -> Verified | Stable expected size+digest/signature; rename verifies published destination; Delete verifies exact authorized source identity and protected-path exclusions |
| Verified -> InventoryCommitted | Targets alone atomically commits Library MediaFile/bindings plus Target/RequestItems and operation stage; raw intake enters Review with unsaved ImportProposals, no fake MediaFile |
| InventoryCommitted -> SourceDeleted | Explicit deleteSource and engine-safe proof: unlink exact source; rename/already-gone source verified as no-op; Copy retains source |
| SourceDeleted -> Done | Verify expected final condition, acknowledge Engine permit, release claims; notify once |
| any active stage -> Retry -> saved resumeStage | Transient I/O/backoff, source/destination evidence survives restart; executor reacquires lease |
| any active stage -> NeedsOwner | Digest/identity conflict or destructive ambiguity; keep claims and original, explain action; no infinite retry |
| Pending -> Superseded | Confirmed Delete atomically takes over a not-yet-executing Rename's claims; no filesystem action by superseded operation |

If Rename is already executing, Delete waits for it to settle, then acquires the resulting
exact final/partial claims; it never races publication. Pending Delete can be persisted
before detach but cannot execute until Engine confirms detach+drain, or safely unselects/
drains only removed pack files without disrupting others. Startup observes both sides and
advances this same executor; no third rename loop. Owner pause/removal fences operation
tokens before the final inventory commit; a settled rename followed by removal must be
deleted via the ordered Delete, never silently published as new active ownership.
Active-pack deletion uses Engine PrepareDelete: detach/drain the removed file bindings
and redirect boundary fragments into .unwanted before any unlink. Proof must guarantee
the old physical path cannot be recreated. Otherwise leave the exact Delete pending until
the remaining selected set completes and manager detach/drain succeeds; API removal is
immediate but freed bytes are never claimed prematurely. FileExecutionProof carries the
actual Engine confirmation to Library.AdvanceOperationAsync.

Swap keeps old partials **detached and not seeding** after the initial replacement proof.
Delete only after replacement finishes OR exceeds old completed selected bytes at switch
at sustained Good rate (>=64 KiB/s continuously 5 min). No deletion merely after 64 KiB.
Disk pressure may release old fallback bytes earlier only with owner-visible explanation
and recorded SwapDecision. If old file is
complete/owned (Upgrade/Replace), delete after new filing+verified inventory commit.
For a Plan split across hashes, apply completion/byte-baseline+Good proof per old target
file group, not aggregate progress that could discard an unstarted episode's partials.
Old sidecars attach by MediaFile.parentMediaFileId and recorded exact paths; same show's
other files and shared selected pack items are not “leftovers”. Shared hash manager is
removed only when no selected incomplete file still needs it; unselect removed episode files and recalculate
boundary pieces. Offline originals defer deletion, never falsely report freed bytes.

Delete preview returns bytes/files, exact path plan, protected paths and failures.
Confirm stores removed Target+retired links+settlements+Delete operations then detaches/
drains engine (per-file safe unselection for shared packs); executor waits for that proof.
UI projections immediately omit removed rows; failed delete retries privately.
Only explicitly confirmed owned paths and known partial siblings may be removed.
Use physical key checks before unlink; don't follow links, delete roots or shared show
directories. Prune only empty descendants. Narrow episode deletion of a pack is allowed
through MediaFile/DownloadFile ownership, never deletes wider packs.
Track-in-place external files require explicit path confirmation for Delete files.
`deleteFiles=false` removes intent/engine associations but retains Owned media.

Moving title to another root is explicit copy -> SHA-256/piece verification -> inventory
commit -> source deletion. Roots can go offline midway; operation retries with original
intact. Existing layout tidy is idempotent, respects pinned paths and claims, cannot
silently replace a same-sized unclaimed file (OPS-656).
