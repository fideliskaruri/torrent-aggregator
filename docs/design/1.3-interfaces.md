# 1.3 Compile-time contracts and API preservation

Executable specification: `backend\src\Domain\Enums.cs`, `Records.cs`, `Interfaces.cs`.
Only records, enums and interfaces; no host, repositories, pure-logic implementations,
background services, EF entities or MonoTorrent dependencies. Build:

```powershell
dotnet build backend\TorrentFlow.Backend.slnx
```

All arrays are `ImmutableArray<T>` (never default on a valid result). Nullable facts stay
nullable. DateTimeOffset is UTC; unknown dates aren't guessed. Records are transport
snapshots, not mutable ORM objects. JSON only at HTTP, typed Setting envelopes, provider
cache and historical legacy-context boundaries; **Plan inputs/outputs are strongly typed**.
StoreRow.Id on Release/Verdict means normalized hash; Setting means section name.
Domain enum casing does not dictate web casing; Api explicitly maps it.

### Source streaming and completeness (OPS-680)

`ISources.SearchStreamAsync` adds cumulative immutable `SourceResult` snapshots;
`SearchAsync` remains the final-snapshot port and `TestAsync` uses the same gate.
SourceResult's positional constructor is unchanged; additive `Complete` and
`Diagnostics` properties distinguish a complete successful answer from a truncated
window, partial page pool, timeout, error or cooldown. `SourceDiagnostics` records
code, queue wait, request count, last HTTP status, first start, returned count and
truncation. Find must cache only Complete answers, not a successful HTTP status.
The additive `UpstreamElapsed` diagnostic measures HTTP headers/body time including
connection setup, separately from gate queue wait.
No implementation body is added to Domain. Sources reads typed settings through
short-lived keyed Find Store scopes, not a Store implementation reference.

### Parser name-evidence additions (OPS-667)

`IParser` remains unchanged: `Parse(string)` and `NormalizeInfoHash(string)`.
`ReleaseParser(int latestReleaseYear)` requires an explicit cutoff (1900..9999);
composition may supply the current UTC year + 2. Parser itself never reads the clock.
Null names are rejected; names longer than 16,384 characters are rejected rather
than silently truncated. Windows paths use the final filename; `RawName` preserves
the original input. Grammar uses culture-invariant non-backtracking regexes.

The existing `ParsedRelease` positional constructor remains compatible. Additive
init properties are `Kind` (`ReleaseKind`), `Foreign` (`ForeignStatus`: Unknown/No/Yes),
`Unsafe`, `EpisodeRanges` and `AbsoluteRanges`. Legacy `Ranges` combines both range
systems; consumers needing coordinates must use the separate arrays. `ClearlyForeign`
is true exactly when `Foreign=Yes`. Unknown language is not a refusal. Explicit
English wins over non-English markers; dual/MULTi audio exempts refusal without
inventing verified English tracks; subtitle-only markers do not prove foreign audio.

Kind, pack and range properties are name claims, never confirmed coverage or work
identity. Extras are Other; explicit within-season ranges are Episode rather than
SeasonPack. Under the approved **OPS-671 structural policy**, Movie means one
unqualified title, not a verified film: no coordinates/pack/non-feature markers
defaults to Movie regardless of container, unfamiliar title, junk or quality.
Unsafe flags do not change that kind. Other requires explicit extras, trailer,
teaser, sample, production files, music, books, subtitle/font-only or software
markers. Date-shaped software versions/PC! and explicit update/patch versions
are software evidence; a video encode's standalone `v2.1` is not.

Audio-format tokens (MP3/FLAC/AAC) are not independently non-feature evidence when
the name advertises a video source, video codec or resolution. Explicit
OST/soundtrack/album/theme/ED/OP-song markers still establish music even with video
encoding tags. Independent book/software/extras markers remain Other; removing an
audio token must never erase those separate reasons.

Without season/episode facts, [BD]/BD-box or Batch/Complete/Collection cues claim
CompleteSeries; no catalog lookup decides whether the named work is a series.
Bare numbered seasons still claim SeasonPack. Title adjectives such as "A Complete
Unknown" are not completeness claims. Name-visible short scene dates are masked
before unqualified episode extraction. Corpus policy changes have a separate
row-specific audit. Check owns actual payload safety; Plan owns work identity and
eligibility against Metadata, runtime/size and file evidence.

The old shapes **must not** be ported: TorrentSearchService doing Sources+Check+Plan;
WantedQueue doing Find+Plan+state; GrabService and ReleaseSwapService separate queries/
picks; MonoTorrentBackend doing Library placement; HeaderProbe owning another client;
ReleaseRanking dedupe choosing max seeds. Each behaviour is allocated above once.

## Store protocol and owners

ReadAsync<TRow> maps the CLR row type to one known table, translates StoreQuery's named
filters to predeclared EF predicates, caps limit 1..500 and uses an opaque stable cursor.
Filters unsupported by a table are errors, not silently ignored. Id/Hash are exact
lookups; WorkId traverses Episode/Season/Request associations where needed; DueAt is
<= timestamp for lease/retry/cache work; Before is age cutoff. Stable order PK by default,
createdAt+PK for history, rank+PK for due Target; Targets computes current priority across
eligible rows (no stored class). No caller SQL/LINQ expression.
StoreOrder explicitly chooses PrimaryKey/CreatedNewest/DuePriority/CheckedNewest;
unsupported orders are rejected. SeasonId/RequestId/RootId/SourceId are exact named
filters, not arbitrary column bags. WorkSnapshot and TargetReadModel assembly uses these
ports, not exposed DbContext.

CommitAsync commits **all** Writes/Deletes under one SQLite transaction. ExpectedVersion
numeric means CAS existing version. With both ExpectedVersion/ExpectedRow NULL a write is
insert-only (an identical receipt retry may return its existing result). Unversioned
mutable rows (association role/selection, Attempt close, operation lease/stage, settlement)
require ExpectedRow with the entire exact previously-read row, compared inside the same
transaction; this is row-CAS, never last-writer-wins. Deletes use the same conditions;
claim release cannot delete another executor's reassigned path. Immutable history cannot
be overwritten even with row-CAS; only documented open->closed/evidence/pruning fields
are mutable. Versioned writes require
new version=old+1. Conflicting IDs return Conflict without partial changes. References,
unique claims and selected missing-set are validated transactionally. No network or
file operation await inside commit. Busy timeout exhaustion yields retriable failure,
never “the item doesn't exist”.

StoreOwner is a descriptive contract, **not authorization**: injected Store capability
is scoped to registered module, checks table/column ownership in 1.1, cannot elevate by
passing StoreOwner.Converter. Converter capability only exists in the offline tool.
Library returns unsaved rows only; **Targets is the sole committer of all joint changes**.
Library owns semantic validation of paths/inventory, not a second commit. Check also returns
unsaved evidence; **Targets commits Verdict plus Release file enrichment**, Check never
self-commits it. Scoped Targets capability explicitly permits ONLY these exceptions:

| Exception | Permitted tables/columns | Required guard |
|---|---|---|
| Admission / filing / cleanup | DownloadFile.partialPath/finalPath/physicalKey/mediaFileId/enginePath/filed (plus Targets' selected/targetId) | Library proposal+hash-bound mapping; filed enginePath equals MediaFile.path |
| Inventory / scan / operations | MediaFile all columns; WorkFolder all columns; FileOperation all columns; FilePathClaim all columns | Library returned validated proposal, expected CAS/lease, exact exclusive claims; joint Target/RequestItem settlement |
| Root enrollment / scans | StorageRoot all columns | Library identity/volume/path checks and owner confirmation for configuration |
| Checked release knowledge | Verdict all columns; Release.filesJson/metadataDigest/private/totalBytes | Check result persistable, not cancelled/live; metadata hash immutable; other Release fields remain Find-owned |

No arbitrary Library/Check/Find owner escalation is possible. Store validates proposal
context/foreign keys, DownloadFile-target association consistency and versions; Targets
does not calculate path/signature facts itself. Library executor asks Targets to persist
each operation stage before it proceeds; no network/filesystem await inside that commit.
Metadata/Find may commit their own ordinary catalog/source/cache rows, not these joint rows.
`LibraryChanges` is a typed unsaved bundle of MediaFile, DownloadFile, StorageRoot,
WorkFolder, FileOperation and FilePathClaim rows plus released claim IDs. FilingResult
and ScanResult return it, so scan presence updates and operation-stage recovery can be
committed by Targets without Library self-writes or an untyped result escape hatch.
FileAsync/ImportAsync/ExecuteAsync propose operations and proofs, not independent rename
loops. The one MaintenanceWorker executor is orchestrated by Targets: commit row-CAS
lease+claims -> ILibrary.AdvanceOperationAsync performs exactly ONE filesystem stage and
returns unsaved LibraryChanges -> Targets commits it -> advance the next stage. Recovery
returns reconciliation proposals to the same executor. No Library->Targets runtime callback
or hidden self-commit is required. An owner API may await this executor's completion,
but must never invoke a competing disk worker.
Notification is a transactional outbox: publication/delivery fail independently.

IdempotencyKey is bounded <=128, actor-scoped for HTTP. Persist command/commit receipt
as an immutable Attempt LegacyEvent with deterministic ID `commit:<actor>:<key>`,
legacyContext containing historical accepted counts/outcome (not live progress).
Receipt inserted atomically with effects; identical retry returns it before CAS.
Changed payload with same key -> conflict. Background commits use durable operation/lease
IDs. This uses existing history rather than a new parallel job/receipt side file.

## Typed settings and immediate effects

SettingRow.Value holds only the matching schema-versioned record shape. Public routes
validate whitelisted fields before constructing typed records; unknown keys refused
where today's contract refuses them. Missing optional fields = preserve current value,
not reset defaults. EngineSettings, SourceSettings, MetadataSettings,
RemoteAccessSettings, DesktopSettings, QualitySettings, RequestSettings,
SchedulerSettings and JellyfinSettings are in Domain. Migration is converter-owned
versioned report shape. Source arrays are serialized as the sources section.
Partial writes compare section revision; changes publish immutable snapshots immediately.
Cap invokes Targets reordering+Engine.ApplyQueue, source credentials invalidate cache
revision, root changes wake waits, metadata credential changes invalidate provider caches.
SecretReference stores opaque protected FileId+revision. Never leak secret contents into
Setting JSON, route replies, logs or migration reports. Existing protected file/keypair
material survives; DPAPI/platform protector or restricted file permissions apply.

## Pipeline interaction

1. Api validates role/body, Targets accepts and commits instant intent.
2. Worker ReadAsync scopes pending Target and Metadata WorkSnapshot, asks Library Owned.
3. Find.SearchAsync yields batches while Sources run independently.
4. Targets checks top candidates through Check, then calls Plan. It sends coverage/tier
   feedback to Find using a bounded channel, so Find never judges healthy “early stop”.
5. Plan assignments go to Library.Place; Targets CAS claims still-missing targets and
   commits Download+files+choice; IEngine.Start gets token/paths, not catalog objects.
6. EngineMonitor calls Targets.Observe. After ALL touching pieces complete, Engine
   PrepareFiling drains/unselects/rebinds the file and returns a permit; detach only if no
   selected file remains incomplete. Library's sole executor validates/renames; Targets
   commits inventory+done+RequestItems, then acknowledges CompleteFiling. Filed paths
   remain engine bindings for shared-pack recovery, not reservations.
7. Every failure returns typed Failure with code/plain message/retry/needsOwner. A worker
   stage exception becomes durable waiting and cleanup, not lost dictionary state.

IEngine must not independently admit or reorder: EngineQueuePolicy contains only
downloadId+Run/Stop. Targets alone evaluates cap/windows/Now and atomically writes the
Download.intent cache and related state/association changes before sending the decision.
Engine enforces physical connections/disk safety only. `SelectAsync` follows persistence. `DetachAsync`
removes manager/resume attachment, **never files**. Probe token can detach only probe-created
handles; live snapshot never creates Verdict. Final files survive normal completion.
Cancellation belongs to operation lifetime: HTTP cancellation before commit may abort;
after accepted commit durable worker is independent. Shared search waiters cannot cancel
each other's work.

### Hash ownership and safe per-file filing

All AttachProbe/ReleaseProbe/Start/AdmitFromProbe/Recover/PrepareFiling/Detach operations
serialize on one Engine-owned mutex keyed by normalized hash. No probe attaches to ANY
hash with a Download row, including detached Queued/Paused/Stopped rows; sample live
read-only or return Unknown. Targets grants admission ownership under that lock;
AdmitFromProbe consumes the capability exactly once, drains writes, resets selected
bindings and invalidates cache+hash-checks (or safely transfers the existing manager).
Start rejects another registered handle instead of silently duplicating it. A metadata
wait attachment also transfers through AdmitFromProbe after safety/Plan admission.
Release of a consumed handle cannot detach the production manager.
Phase 3 must prove actual MonoTorrent isolation/handoff, not merely assume locking suffices.
Fresh SwarmEvidence may return AdmissionHandle held at most 30 s after measurement;
cached/live evidence never carries a handle, and tokens never persist in Verdict.
ClaimAdmission reserves the hash under its mutex BEFORE the Store admission commit
(90 s expiry), fencing new probes across the DB->Engine handoff gap. A failed CAS releases
only that claim/handle; successful commit then Start/AdmitFromProbe consumes it. Startup
Recover loads every Download row into the registry before probes can attach, including
Stopped/Queued/Paused. Store intent always precedes payload. MetadataWaitAttachment returns
the same ProbeHandle capability for transfer, not an unrelated string token.

PrepareFiling receives Library-chosen final bindings, not catalog names. It checks all
pieces touching every file including boundaries, drains writes, sets DoNotDownload and
rebinds the manager path under the hash lock, then grants an operation/path-scoped permit.
Library alone publishes the same-directory rename while Engine bars touching-file writes;
CompleteFiling acknowledges publication or rolls back a failed binding before releasing
the fence. Persist operation+final binding intent before rebind; restart reconciles permit/
operation/disk under the same lock. DownloadFile.enginePath+filed retain final paths for
pack recovery, selected=false; retired target links do not mean missing torrent metadata.
If Phase 3/5 proves MonoTorrent cannot safely rebind, use whole-selected-set completion
before filing (1.5 option b), never unsafe per-file detach/re-register.
Delete operations require FileExecutionProof (manager detach+drain or PrepareDelete permit).
For an active shared pack, PrepareDelete drains and detaches the removed files from their
old physical bindings, redirects unavoidable boundary fragments into .unwanted, and
confirms no writes can recreate the deleted path. If safe per-file detach/rebind cannot
be proved, defer disk deletion until the remaining selected set finishes and the manager
detaches; never stop other incomplete selected targets just to delete a partial.

Metadata wait is outside payload cap, max 3 top Unknown hashes per target, no payload
selection or library reservation; connection/global Check budgets still apply. Expire
attachment after 45 min; it is reconstructible from waiting intent, not Attempt work state.
AttachMetadataWait/ObserveMetadataWait/ReleaseMetadataWait have capability tokens; a hash
shared by multiple targets still has one manager, with independent bounded waiters.

#### Phase 3.3 implementation boundary (OPS-695)

`backend/src/Engine/MonoTorrentEngine.cs` implements the Domain port using one MonoTorrent
3.0.2 client. Its lifecycle lock serializes ownership, connection/selection changes and
drain/permit operations. The composition root supplies settings and a CAS port-persistence
callback; Engine does not reference Store, Targets or Library. Cache/DHT/metadata/resume
artifacts live under `<data>/engine`. Payload selection is always supplied as complete,
absolute file bindings. No automatic payload cap, catalog naming or payload deletion
is implemented in Engine.

Metadata-only attachments request **zero payload pieces**. Therefore their payload
`BytesDelivered` is honestly zero, even when peers delivered the file list. Development
responses separately report `protocolBytesDelivered` (metadata plus peer protocol traffic).
Engine returns raw measurements with Unknown, not a fabricated Good/Dead verdict. Phase
3.5 Check owns verdict classification. `ObserveProbeAsync` measures at most sixteen pieces,
bounded to 4 MiB, using an excluded-piece mask in the pinned package's requester. Probe
blocks bypass the shared cache and go only to engine-data probe files. Delivered bytes
count hash-verified pieces, not protocol or corrupt payload. Metadata wait remains
strictly metadata-only. Lack of deliberately requested payload is not evidence of Dead.

MonoTorrent 3.0.2 keeps its metadata-only `StartAsync(bool)` and raw info metadata
non-public. The pinned adapter validates those two members and fails closed if they
change; ordinary `StartAsync()` is never substituted for an unknown-metadata probe.
Admission transfers the same manager under a per-hash mutex, stops/drains and explicitly
flushes its disk writes, invalidates the probe picker/cache-bypass registration, resets
every binding/priority, performs a full piece recheck, and deletes the vacated probe
directory. Fresh piece-probe admission capabilities last 30 seconds; claims at most 90
seconds. A late release cannot
detach the admitted manager. Completed selected sets stop seeding immediately, with a
tick as a retry safety net.

Per-file filing remains **option (b)** from 1.5: whole-selected-set completion followed
by detach/drain. Live-pack rebind/delete is refused while other selected files are
incomplete. Phase 4.3/5 must prove option (a) before replacing this fallback.

`Api/DevEngine.cs` exposes Development-only, trusted-loopback owner diagnostics:
`POST /api/dev/engine/probe` (`magnet` or `hash`, `seconds` 1..60),
`POST /api/dev/engine/add` (`magnet`, explicit zero-based `files`, absolute `savePath`),
`GET /api/dev/engine/torrents`, and `DELETE /api/dev/engine/{hash}?data=true`.
Additional `/intent` and `/recheck` POST routes support real lifecycle verification.
The probe fixture accepts `pieces:true` for payload measurement, `retain:true` for a
30-second capability consumed by add's `probeToken`, and `trackerless:true` for genuine
DHT-only metadata diagnostics (no injected public trackers).
`GET /api/dev/engine/torrents?pieces=true` adds verified piece indices solely for
restart evidence; ordinary diagnostics omit that potentially large live bitmap.

DHT starts before torrent admission with compact cached nodes plus four IPv4 bootstrap
routers. TCP listeners bind IPv4 and IPv6 where supported; MonoTorrent 3.0.2 DHT itself
is IPv4-only. Its incompatible bencoded-save/raw-load cache is replaced by one bounded
compact cache, saved periodically and at shutdown, never overwritten by an empty table.
Initial routing-bucket refresh is bounded; it is not a second torrent client or scheduler.
An idempotent DHT adapter preserves outstanding queries across the client's first-torrent
start, and saves nodes before the last-torrent stop. A zero-byte engine session marker
distinguishes unclean shutdown: stale fast-resume flags are replaced by one full disk
recheck on recovery, without persisting application progress or transfer counters.
Engine serializes atomic fast-resume writes itself, with binding/file fingerprints,
instead of MonoTorrent's overlapping automatic writers. Clean restarts load the pinned
package's FastResume; unclean restarts or changed files recheck before requesting bytes.
An unclean startup invalidates **all** engine fast-resume artifacts before recovery,
including detached Queued/Paused/Stopped downloads. A later clean session cannot trust
a stale checkpoint for a download that was not attached during the unclean session.
The dev fixture binds selected files to `.partial` paths and skipped boundaries to
hash-scoped `.unwanted` paths. An optional magnet `xs` supplies a public, hash-pinned
HTTP `.torrent` response, bounded to 20 MiB/6 s; peer-only magnets need no `xs`.

The dev fixture checkpoints MonoTorrent's binary state (paths, priorities, resume and
dev-only Run flag), excludes probes, and restores it only in Development. This is not
an application Download/Target store. Production recovery must supply Store's authoritative
Download/File rows through `RecoverAsync` before admitting checks. The temporary EngineHost
tick is the EngineMonitor role for this phase; do not keep a second independent monitor
when Targets orchestration is implemented. Real HTTP/file proof is in gitignored
`tools/.engine-proof/`; build output is isolated there when a concurrent catalog server
holds `Api/bin` open.

### Pure Parser / Plan acceptance contract

Parser normalizes separator punctuation, Unicode dashes/apostrophes, whitespace, brackets,
leading group tags and trailing hashes before interpreting title+numbers; parse a full
release once, not separately in every adapter/caller. Preserve numeric title words and
years. Cover SxxEyy/NxYY, season words/ordinals, anime dash/bracket absolute numbers+v2,
range/multi-season/batch, OVA/OAD/recap/special/movie, Part/Cour (not episode ranges).
Regex execution <=1 s, compiled dynamic-pattern cache <=128; full-width decimal digits
parsed as numeric Unicode values rather than int.Parse on raw strings. Corpus is the
acceptance oracle, not new unit tests.

Plan emits a Rejection for **every refused candidate and each uncovered item**, with
scope/hash/code/explanation. Hard gates in this order:
1. valid normalized hash; work identity matches a labelled verified allowed name; strong
   token matching plus compatible kind/year rejects Scorpion King; absent year not proof.
2. film-shaped vs episode-shaped; explicit episode exactly maps stable season/episode;
   seasonless single only S1 unless confirmed metadata maps it; sequel premiere year
   belongs to that season/provider entry, not first-season year.
3. resolution floor, owner max bytes, broad runtime/bitrate plausibility, no CAM/junk.
4. full file-list safety: dangerous extension anywhere including skipped files; trim
   Windows trailing dots/spaces (`.mkv.exe.` remains executable). Selected set needs video,
   never archives-only/no-video. Same dangerous/archive/sample lists ported from
   MediaFileRules to one Plan-owned pure file-list gate, not independent API/Engine
   lists. Parser only returns naming facts; Library separately validates content
   signatures, a different fact than filename eligibility.
5. clear foreign markers (RUS/LostFilm/VOSTFR/raws etc.); unknown accepted without I/O.
   Explicit compatible English/MULTi containing English evidence can disambiguate an
   otherwise foreign marker; never originalLanguage alone proving a foreign release.
6. current/work-global Blocks and explicit tried-hash policy; safe owner scoped-block
   override only. Fresh verdict band drives ranking described in 1.4.

For finished-season packs: each selected video must have exactly one unambiguous
SxxEyy/NxYY mark, belong to requested season, be within metadata count, and be the only
video for that episode. Ignore samples/extras/double-episode/range videos; ambiguous
duplicates are uncovered, never choose arbitrarily. Archives/disc images/programs or
other-season videos reject the whole pack. Bare/absolute pack filenames are not silently
accepted by the old strict-map behaviour; permit them only when Metadata has a confirmed
bijective absolute map and Parser returns exactly one identity, with a recorded mapping
reason. A claimed complete pack missing files cannot claim that missing coverage;
partial safe coverage is explicit and uncovered episodes keep searching. Sidecar
selection associates only the selected video, preserves language/forced suffixes.
Storage reserved bytes use union of touched pieces, not sum of independently rounded
file sizes. A pack never selects owned Acquire episodes. The **specific** Replace target
is exempt from its own owned exclusion only: Upgrade requires known resolution strictly
above best owned, Replace at least equal, and all other quality/safety gates remain.
PlanInput carries Target.replacementMode and Owned video qualities for this single gate.
SelectedFile.targetId is NULL only for ExplicitRaw; catalog assignments require the exact
known target for every selected video/sidecar, consistent with DownloadFile/DownloadTarget.

### Metadata acceptance contract

TMDB v3 key/v4 bearer remains supported and masked. Enabled TMDB/AniList/Cinemeta plus
keyless iTunes/TVmaze lookup query in parallel, relevance interleaves films/series/anime;
no category walls or first-plausible-provider identity merge. Fuzzy title query normalizes
typos/whitespace/Unicode, respects remake years in cache keys. Exclude adult/person
records. Explicit providers IDs always resolve (including search-result title URLs),
failed/rate-limited/not-found are separate outcomes. Missing key does not disable keyless
home/search/details. English display wins, original/romaji/synonym names remain labelled.

Provider caching: work database 7 days; successful memory detail 30 min, transient
miss 3 min; title search 5 min fresh/24 h stale, stale only if all providers failed.
Never cache a failed/partial result as confirmed empty. Alternative names: 1 day success,
1 min failed/empty, 4 s lookup. Optional enrichment bounded 450 ms/4 slots/top16/6 distinct
names, never holds torrent Find indefinitely. TMDB discovery one 10 s deadline.
AniList query coalescing 60 s, actual provider gate 90/min with 5 foreground reserve and
60 s startup grace; this is site protection, not an owner application quota. Respect
real Retry-After, no inline429 retry; retain a separate bounded provider queue.

Fribb mapping loads last-good cache at startup, conditional refresh weekly; invalid/
oversize/failed download never replaces it. Keep verified vs suggested vs rejected links,
drop retired claims only on verified map-version update, remove names only from retired
provenance. Kind/anime/format from provider; episodes never guessed from release names.
Split-cour/sequel chain shares title-page/acquisition season shape; listing starts snap
within 2 episodes, <=40 listing seasons, provisional interrupted chain stays Unknown.
Partial anime map cache 1 min/mapped 1 h/chain-only 5 min; unknown/not-yet-aired doesn't
advance Follow start/cursor. Preserve stable Episode ID across confirmed renumbering;
unconfirmed mappings don't create actionable episode claims.

Browse registry remains stable and daily sticky, no random shuffle, every visible title
at most once; rails filter not-out/in-cinemas with the same HomeRelease evidence as title
detail. Without home-release evidence film theatrical window defaults 21 days; TMDB
confirmed Digital/Physical/TV evidence supersedes it. ExtrasAsync returns all season
metadata, similar/part-of, score provider/votes/certification and shared release gate;
RecommendAsync receives saved intent seedWorkIds, never guesses from torrent names.
Episode displayed metadata can fail without erasing already-local availability.
Canonically resolve poster once in Work for home, watchlist, requests and notifications.

typed result to the exact captured wrapper/status/query/body, never serializes Domain rows.

available source descriptors and pagination totals. BackfillQuery preserves optional
watchListItemId/fromSeason/toSeason/episodesPerSeason/avgEpisodeGb; Targets supplies saved
item title/default start, Library returns real free bytes and estimate (not a fake Plan).
Targets passes BackfillEstimateInput with that resolved title/start/root to ILibrary,
so Library does not duplicate metadata/watchlist resolution.
RecoveryResult includes dataDirectory/downloadDirectory/hasMedia for the existing GET,
plus external source discovery; POST recovery stays explicit Library import confirmation.
UntrackedFilesAsync is a typed internal scan query (not a replacement for the captured
POST). For that POST, ILibrary.PlanUntrackedDelete returns exact leased Delete operations;
Targets' sole executor completes them before returning existing success/error wrapper.
Refuse root/absolute/escaping paths, links, internal directories and any MediaFile/
DownloadFile/active operation claim including tracked descendants; no broad root deletion.

work/episode identity known it cannot create a film/episode Target with guessed numbers.
